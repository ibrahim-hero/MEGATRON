# Product / UI / UX

## The experience

MEGATRON’s Mission Control turns attention economics into an interface. The first question is: **does any work need me?** The second is: **what evidence makes this result usable?** Technical internals stay inspectable without becoming the default reading burden.

The visual system uses a deep navy canvas, restrained blue primary actions, amber decision states, green verified outcomes, and red failures. Typography uses system sans-serif text with monospaced IDs, commands, fingerprints, and output. Cards have consistent borders and spacing; modal elevation is reserved for concrete decisions.

## Screens

1. **Overview:** attention-first mission cards, real execution counts, measured spend, work history, and project-intelligence context.
2. **Mission detail:** scope/mandate, factual timeline, actual before/after changes, independent evidence, resumable checkpoints, and delivery artifacts.
3. **Decision modal:** explicit consequence, change set, verified fingerprint, and approve/request-changes controls.
4. **Knowledge:** cited search results with source hashes and an import-relationship map.
5. **Workflows:** dependency-aware repository workstreams with separate mission links and node artifacts.
6. **Models and budgets:** capability routes, configured prices, and observed verification outcomes.
7. **Benchmarks:** transparent synthetic/live mode, expected outcomes, false-ready rejection, costs, and trace details.
8. **Integrations/settings:** sources, tools, validated skills, and revision-aware configuration.

## Interaction rules

- `Ctrl+K` / `Cmd+K` opens the command palette.
- One structured question is answered through one clear form.
- Approve opens a reviewable decision; Escape closes a dialog without approving.
- Pausing processing preserves intake and stored work.
- Poll updates avoid replacing a focused editor or open dialog.
- Raw receipts expand progressively beneath concise states.
- Status labels accompany semantic colors.
- Visible focus rings, labeled controls, a skip link, and reduced-motion support are included.
- The mobile layout keeps all screens reachable through horizontally scrollable navigation; source tables scroll inside their own containers.
- Dark and light themes share the same semantic state model.

## Product assets

The shipped screenshots are taken from the actual running application, including real verification receipts and an approval-bound patch. The walkthrough video follows that same application. Demo mode is prominently labeled so a scripted provider is never represented as live intelligence.

The VS Code extension lists the same missions, renders script-free change review, and stores optional server tokens in SecretStorage. The mobile web manifest supplies a home-screen app surface backed by the same API.

## Product evaluation

Measure verified completion, regressions, engineer interventions, time, and cost on equivalent tasks and budgets. Benchmark scripts establish harness correctness; configured-provider runs establish model-system performance. The original vision’s percentage targets are goals to evaluate, not results to advertise.
